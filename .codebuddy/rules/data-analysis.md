# 数据解析任务规则

> 适用：用户给出一份或多份**已运行的回测报告**，要求分析 / 对比 / 下结论。
> 与 `backtest-credibility.md` 分工：那份管「**怎么跑**可信的回测」，本文管「**怎么读**报告、怎么写结论、AI 的行为边界」。
> 跑实验的纪律（走生产编排层、两个必做对照）不在本文重复，直接引用。

## 零、任务边界

- **对象只限已落盘报告**：路径以 `core.config.REPORTS_DIR` 为准（当前 `E:\stockanaly-data\backtests`），
  只读 `backtest-*.json` + `index.json`。
- **不自行启动回测 / 探针脚本**。发现需要新数据时：
  **说明缺什么、给出建议参数，请用户运行指定报告**，不要自己跑
  `backtest.run_backtest` 或 `scripts/*_probe.py`。
  - 例外：**单测可以直接跑**（秒级、验证代码正确性、不产生新报告）。
  - 理由：① 全市场回测冷启动 7 分钟；② 自跑容易引入口径不一致、污染对比；
    ③ 参数选择权在用户。
- **「请运行特定报告」必须给全参数**：策略 id、区间、池子 / 剔除项、开关取值、seed、
  是否与现有报告同口径。只说「再跑几组」等于没说——跑出来又不可比。

**分析脚本的边界**（「不自行跑」不等于「不能写脚本」）：

- ✅ 可以写**只读**临时脚本，读报告算指标 / 阶段拆分 / 集中度
- ❌ 不改业务代码、不跑回测 / 探针、不写报告文件
- 临时脚本头部标「待清理」，**用完即删**；不要留在仓库里
- 可复用的分析（阶段拆分 / 爆仓诊断 / 集中度）沉淀到 `scripts/`，别每次重写一次性脚本

## 一、分析前的可比性检查（不满足就别比）

按 `backtest-credibility.md` §一逐项核对：

- [ ] `schema` 版本（结构不同 → 字段含义可能变了）
- [ ] `scope.exclusion.spec_version` / `spec_signature`
- [ ] `strategy.version` / 策略 id
- [ ] `pool_signature`（或 `scope.exclusion.dropped` 只数 + 区间端点 + 判定基准日）
- [ ] 区间、成本（`commission`）、`initial_capital`、`limit_open_policy`
- [ ] 执行层开关：`abnormal_filter` / `max_buy_price` 等

任一项不同 → **不可直接对比**：只能分别描述，或请用户按同口径补跑。
**同指纹不等于同池子**——外部数据取没取到、区间端点都不在 `spec_signature` 里。

**列全差异清单，不能只盯关心的那个变量**：

- 对比 N 份报告时，**先把所有差异字段列成表**再分析，而不是只看「这次改了什么」。
  佐例：分析 `max_buy_price=50/100/无` 三份时，同期还合入了 `near_severe` 默认勾选——
  若 `abnormal_filter` 也变了，把收益差全算到价格上限头上就是错的。
- **唯一变量**才能归因到单一开关；多个变量同时变 → 只能分别描述，
  或请用户按单变量补跑。
- 差异清单至少含：上表全部字段 + 报告生成时间 + 策略参数（`params` 对象）。

**报告完整性检查**（没跑完的不当结论依据）：

- [ ] 任务状态是**完成**（不是失败 / 中断 / 进度未到 100%）
- [ ] `errors` / `data_errors` 为空（有内容要看是不是影响本次结论）
- [ ] `build_failures.shown` vs `count` 是否截断——**计数是全量、明细可能被截**
      （佐例：09:22 那份 count=2378 / shown=2000，明细少 378 条但统计数可信）
- [ ] `equity` 天数覆盖声明的区间（不是半截数据）
- [ ] 分层统计各组都有值（不是某一组空着被当成 0）

## 二、多维度指标（至少一起给，不许只报总收益）

| 维度 | 字段 | 为什么必须看 |
|---|---|---|
| 总收益 | `metrics.total_return` | **只作参考，不作结论依据**（换一次抽样差两个数量级） |
| 风险调整 | `metrics.sharpe` | 跨报告可比的主指标 |
| 回撤 | `metrics.max_drawdown` | 长区间回撤显著放大 |
| 资金效率 | `metrics.capital_utilization` / `return_per_utilized_capital` | 过滤 / 空仓时收益下降但效率未必差 |
| 换手 | `metrics.turnover_annual` | 决定滑点与实盘可行性 |
| 成交笔数 | `metrics.num_trades_eff` | **既是样本量，又是口径指纹**（笔数突变 = 口径变了） |
| 市场环境阶段 | 见下方「阶段拆分」 | 同一策略可能只在某段行情有效，整体指标会把这个事实平均掉 |

**阶段拆分（必须做，且与三道闸的「跨区间」不是一回事）**：

- **数据来源只限已落盘报告**：用报告里的 `equity`（日净值）+ `trades`（逐笔）
  **离线**算，**不重跑回测**——这跟零章「不自行跑」一致。
- **怎么拆**：按报告的**时间轴**切成若干连续阶段（自然年 / 半年 / 自定义区间），
  **每段单独算**夏普 / 回撤 / 收益 / 笔数 / 负收益日占比；
  同时给同段的 `equity_benchmark`（等权全池基准）算超额。
  - 也支持按「大盘状态」拆（牛市 / 熊市 / 震荡）——大盘序列取 `index_bars` 或
    `equity_benchmark`；口径与 `scripts/jwzz_prod_probe.py --mode period` 一致。
- **必须回答的问题**：是「每段都有效」还是「某一段独扛」？
  - 某段夏普显著低（如 <1.5）或收益为负 → 标注**行情依赖**，
    结论写成「在 X 段有效，Y 段失效」，不许只报整体夏普。
  - 各段都稳 → 才可说「跨行情成立」。
- **笔数少的段要分清原因，不能一律当「样本不足」抹掉**：
  - **策略主动规避**（该段空仓 / 极少操作，但行情数据完整）→ 这本身就是**择时 alpha**，
    要作为结论写出来：「X 段大盘 −15%，策略空仓、0 笔交易，规避了下跌」。
    **不许**因为笔数少就合并段或标注「样本不足」——那等于把策略的优点判成缺陷。
  - **数据不足**（该段行情缺失 / 报告区间没覆盖）→ 才标注「该段数据不足，不下结论」。
  - 笔数少时**夏普/回撤的统计可靠性低**（分母小）：这段改用**绝对收益 + 基准超额**
    表述，不要硬报一个几位小数的夏普当成强证据。
  - 三章的「≥1000 笔 / ≥3 份」是**整份报告与跨报告对比**的下限，
    **不适用于单个阶段**（见三章边界声明）。
- 佐例：`jwzz_cross` 生产口径按年拆，夏普 1.77~4.29（最低 1.77），
  2022 熊市等权基准 −10.62% 时策略仍 +98.70% → 才认定「跨行情成立」。
  详见 `docs/backtest-credibility.md` §二.9 的换区间表（**唯一可引用的生产口径数字**）。

**读指标的口径陷阱**（读错比不读更糟）：

- `equity_benchmark` 是**等权全池**基准，**不是**用户在结果页选的指数——
  卡片名「等权全池收益」就是这个意思；别拿它当「沪深300 超额」来读。
- 逐笔 `ret` **不是单票真实盈亏**：引擎按 `|Δw| × 调仓日前的组合净值` 记账，
  与该票价格脱钩，**可以方向相反**（实测真实跌 14.9% 记 +18%）。
  想知道单票真实盈亏，用 `buy_price` / `sell_price` 自己算。
- 夏普的**年化因子 / 无风险利率**跨报告要一致，否则数字不可比；
  报告没记就说明「按默认口径算」，不要假设两边一样。
- **能从报告离线算的就别要求重跑**：收益集中度、阶段拆分、逐票贡献、超额，
  `trades` / `per_stock` / `equity` / `equity_benchmark` 里都有。
  要求用户补跑只能是「报告里确实没有」的维度（如新开关、新池子）。

- 结论里出现「X 比 Y 好」→ 必须有**夏普 + 回撤**支撑，不能只拿总收益。
- 收益与夏普背离时（总收益低但回撤小、夏普不差）→ **两者都写出来**，
  不要挑一个下结论。
- 加了阶段拆分后若「整体 A 好、分段 B 好」→ **以分段为准**，并解释整体指标
  为什么掩盖了差异（通常是某段的极端收益拉动）。

## 三、样本容量下限（不满足 → 只描述，不下结论）

> **边界**：本章下限适用于**整份报告的整体判断**与**跨报告对比**，
> **不适用于二章「阶段拆分」后的单个阶段**——策略主动空仓造成的低笔数是择时能力，
> 不是样本缺陷（见二章「笔数少的段要分清原因」）。

- 单份报告成交笔数 **< 1000**：不给「策略有效 / 无效」的判断，只报观察。
- 跨报告对比 **< 3 份同口径样本**：只能说「这一组的观察」，不能说「通常 / 一般」。
- 股票池 **< 500 只**，或当日候选票不足 `top_n × 3`：
  打乱排序 / 随机对照组天然贴近基准，结论会反转
  （佐例：200 只子集说「排序只贡献 25%」，1500 只说「贡献 96%」——
  见 `docs/backtest-credibility.md` §二.4）。
- 爆仓 / 净值变负（`total_return < -100%` 或单日收益 < -100%）：**直接剔除**，不纳入统计。
- 不满足下限时的输出格式：
  「观察到 X（n=2 份，各 3400 / 3600 笔），样本不足以下结论」。

### 爆仓样本：分两层处理，不是「一律不分析」

净值变负后年化 / 回撤 / 夏普全是失真数字（项目里见过总收益 −101.49%、
单日 −132.25%、回撤 −101.95%），**硬算没有意义**。但「剔除」只针对**绩效对比**，
不等于整份报告没有价值：

| 目的 | 做法 |
|---|---|
| **绩效对比 / 策略排序** | 直接剔除，不纳入统计，也不引用它的任何收益率数字 |
| **失败案例诊断** | 只看**破产前**的行为序列，回答「为什么死」，不碰收益率 |

诊断时用报告里已有的 `equity`（日净值）+ `trades`（逐笔）**离线**算，不重跑回测：

- 破产前的持仓集中度（是否满仓单票 / 少数票）
- 破产时点对应的市场环境（是否踩在极端行情上）
- 逐笔亏损来源（巨亏笔是单票黑天鹅，还是连续小亏累积）
- 是不是口径 / 参数问题（负权重、仓位 >1、成本模型漏算、杠杆）

**只写结论，不报失真的收益率数字**；诊断结果归入「观察 / 推测」档，
不拿单次破产案例推广成普遍结论。

## 四、归因纪律

- 多个执行层开关同时生效时（一字板 / 撤单 / 异动 / 价格上限），
  **按 `feasibility.build_failures.reason` 分组各算各的**，
  不要把总收益差全算到某一个开关头上。
- 某开关 `limit=None` 或计数全 0 → 这一组**没有变量**，不参与该开关的对照。
- **前置条件纪律**（易被误用为「要求扩展」）：
  某些条件只在别的条件生效后才有意义——
  例：`near_severe` 预警要等 `abnormal_filter` 开启后才改变成交；
  价格上限在「策略从不选高价股」的池子里永远不触发。
  - 先判断前置条件是否成立 → 不成立就**明确写「本组该条件未生效」**，
    **不要**因此要求用户补跑一大组实验。
  - 只有「前置条件成立 + 样本够 + 用户明确要量化」三者同时满足，
    才建议扩展对照。

**反面证据检验**（下归因结论前必做）：

- 只找支持自己的证据，结论就是自我印证的。归因写完后**主动找反例**：
  - 例：说「价格上限砍掉的是高弹性票」→ 去 `build_failures` 里把被拦的代码取出来，
    对照它们后续走势 / `per_stock` 贡献，看**是不是真的涨得好**。
    若被拦的票其实在跌 → 归因不成立，改写「拦掉的票表现不明，收益差另有原因」。
  - 例：说「某段失效是行情依赖」→ 看同段基准是不是也在跌。
    基准也跌、策略跌得少 → 不是失效，是**相对抗跌**。
- 找不到反例也要在结论里写一句「已查过 X 方向，未见反证」，
  让读者知道这是检验过的，不是挑出来的。

## 五、结论落盘

- 分析结果**更新到对应文档**，不要每次新建 doc：
  - JWZZ 系的结论与数字 → `docs/jwzz-backtest-2026-11-16.md`（**唯一权威**）
  - 通用方法论 / 判据 → `docs/backtest-credibility.md`
  - 功能 / 字段变更 → `docs/changelog.md`
- **同一数字只在一处维护**；其他文档写「见 XXX」，不复制第二份。
- 结论必须标注：报告文件名 / 口径版本 / 样本量 / 分析日期。
- 区分三档措辞，不许混用：
  - **已验证**：多份同口径样本 + 对照实验支撑
  - **观察**：单份报告 / 样本不足
  - **推测**：机理猜想，未做对照
- **不静默改历史数字**：新证据推翻旧结论时，在对应文档写「口径更正」块
  （参照 `docs/backtest-credibility.md` 顶部），说明哪个口径作废、新数字是什么。

**结论要落到「下一步」**，不许停在描述性统计：

- 每段分析结尾给**可操作建议**，从这四类里选（可以多类）：
  - **调参数**：改哪个开关 / 阈值，预期影响哪个指标，需要补跑哪份报告
  - **换策略**：现有策略的问题是哪一类（口径 / 行情依赖 / 集中度），换什么方向
  - **接受现状**：现状已是最优 or 改动收益不抵复杂度，说明为什么不动
  - **补证据**：还缺什么样本 / 对照，给出**完整参数**请用户跑（见零章）
- 建议必须**对应前面的证据**——不能分析完 A/B/C 三份，最后给一个跟它们无关的口号。
