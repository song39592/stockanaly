# 回测可信度纪律

> 展开与佐例：`docs/backtest-credibility.md`。本文只留纪律。
> 全部佐例来自 2026-11-16 一次真实排查（JWZZ 策略族）。两次返工，两个数字：
> ① 同一份生产代码、同一个区间，只因股票池抽样不同，总收益从 **73 倍变到 1359 倍**
>    （而夏普只在 2.7~6.3 之间动）；
> ② 探针**绕过编排层** → 漏掉严格成交模型 → 收益虚高 **46 倍**（8457% vs 183%）。

## 零、执行路径：实验必须走生产编排层（前置条件）

- 对照实验 / 探针脚本**一律走 `backtest.run_backtest`**；
  **不要**直调 `strategies.xxx` + `stats.compute` —— 后者会漏掉
  ① `universe.filter_available`（注入判定）与
  ② `raw_by_code` → **严格成交模型**（一字涨停买不进即空仓、不重分配；
  一字跌停卖不出即延后清仓）。
- 佐例（全市场 2024 / `jwzz_cross` top_n=10）：放宽口径 **8457% / 夏普 6.06**，
  生产口径 **183% / 夏普 1.86** —— 收益高估 **46 倍**、夏普高估 3.3 倍。
- **自查信号**：逐笔里出现 `buy_price=None` / `shares=0` → 走了放宽口径，
  该批结果一律作废。

## 一、结论前必须先过的三道闸

1. **引擎确定性** —— 同参数、同区间跑两次，净值与笔数是否**逐位一致**？
   不一致 → 先查引擎与数据，**别谈策略**。爆仓路径（净值变负）会破坏确定性，
   这类结果直接剔除，不纳入横向对比。
2. **口径同版** —— 两份报告的 `scope.exclusion.spec_version` / `spec_signature`
   是否一致？策略的 `strategy.version` 是否一致？不一致 → **不可直接对比**。
3. **指标可比** —— 横向比**只看**夏普 / 每单位动用资金收益 / 最大回撤 / 换手，
   **不看总收益**。总收益在这套体系里由「池子里恰好有哪些妖股」决定，
   换一次抽样就能差两个数量级。

## 二、必做的两个对照（缺一个，结论就不成立）

- **同池打乱排序** —— 只把「按信号降序」换成「在同一候选池里随机取」，
  分开**集中度**与**选股质量**。样本要够宽：候选池窄时（当日强势票不足
  top_n），对照组天然贴近基准，会把排序的价值**掩盖掉**。
- **换池重复** —— 固定策略 / 参数 / 区间，只换随机抽到的股票池，跑 N 组，
  看收益的**离散度**。离散度大 = 单次跑出的高倍数是抽样产物。

## 三、口径纪律

- 改动**统计口径**（阈值 / 剔除特征 / 判定基准日）→ 手工 bump
  `universe.SPEC_VERSION`；改动**策略算法**或参数默认值 → bump 该策略的 `version`。
  两者随报告落盘（见 `backend-conventions.md` §三）。
- 剔除规则的影响要**单独量化**（剔不剔各跑一次）—— 佐例里剔除 ST / 次新 / 微盘
  直接砍掉 **92%** 的收益，说明收益高度集中在小盘妖股上。
- 收益集中度要看**逐笔 / 逐票贡献**（佐例：前 100 笔贡献 87.7% 毛收益、涉及 97 只标的）
  —— 集中度极高时，单次总收益不可复现。

## 四、判据速查

| 现象 | 结论 |
|---|---|
| 实验收益远高于生产口径 | 走了放宽口径（漏 `raw_by_code`）→ 该批结果作废 |
| 同参数两次跑结果不同 | 引擎不确定 → 先修引擎 |
| 打乱排序后收益几乎不变 | 「信号排序」没价值（排除 bug 后就是口径问题） |
| 打乱排序后收益掉一个数量级 | 排序是真 alpha（可继续深挖） |
| 换池后收益差两个数量级 | 单次结果是抽样产物 → 只报分布，不报单值 |
| 换区间后夏普大幅下滑 | 行情依赖 → 该做的是市场状态过滤，不是调参数 |
