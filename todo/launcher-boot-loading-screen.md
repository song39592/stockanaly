# 后期待办：后端拉起前显示加载界面（启动遮罩 / 进度）

## 背景
启动器拉起后端的链路（`launcher/StockPoolLauncher.cs`）：
- 入口 `Main` — `:35` → `Application.Run(new MainForm())` — `:43`；
- 构造 `MainForm()` — `:445`，同步构建各页面 — `:560-571`，`Shown += Boot` — `:585`；
- 服务定义 `InitServices()` — `:1882-1907`（**不调 .bat**，直接 `ProcessStartInfo`）：
  后端 `python -m uvicorn main:app --host 127.0.0.1 --port 8000` — `:1889-1897`，
  `HealthUrl = http://127.0.0.1:8000/health` — `:1898`；
- 启动主流程 `Boot()` — `:1909-1955`（**后台线程**）：
  1. `PrepareEnv(false)` 环境检查 / 装依赖 — `:1917`；
  2. 读自动启动开关 — `:1919`；
  3. `Probe(HealthUrl, 1500)` 探活，失败才 `StartBackend` + `WaitHealth(后端, 45s)` — `:1925-1930`；
  4. dsh 同理 `WaitHealth(30s)` — `:1936-1941`。
- 等待方式 = **健康检查轮询**：`WaitHealth()` — `:1957-1964`（每 500ms `Probe` 一次）。

**现状（无加载界面）**：只有文字 / 状态灯，**没有 splash、没有加载遮罩**
（搜 `splash` / `加载中` / `启动中`：0 命中）：
- 顶部状态灯 `_lbBackendDot` / `_lbAiDot` — `:500-501`；`_lbBackendDetail` — `:510`；
- 服务页文字「状态：检测中…」— `:676`（后端）/ `:691`（AI）；
- 系统日志「正在启动后端…」— `:1927 / :1938`。

**空白等待发生在**：`Boot()` 从「正在启动后端…」到 `/health` 就绪（最长 45s 后端 + 30s dsh），
以及 `PrepareEnv` 装依赖期间（可能更久）。此期间主窗体已 `Shown`，但**只有状态灯在变**。

## 目标
在 `Boot()` 期间给出**明确的加载反馈**（遮罩 / 加载页：阶段文本 + 进度或已用时 + 失败可重试），
覆盖 `PrepareEnv` 与等待后端两段；就绪或失败后再放行，避免「干等空白」。

## 具体步骤
1. 新增 `BootOverlay`（顶层无边框 `Form` 或主窗体内的全屏 `Panel`）：标题 + 状态文本 +
   进度（不确定进度用跑马灯 / 秒表）+「重试 / 查看日志」按钮。
2. `Boot()` 各阶段回报状态：把 `PrepareEnv` / `Probe` / `StartBackend` / `WaitHealth` 的进度
   经回调 + `Invoke` 更新遮罩文本（如「检查运行环境…」「启动后端服务…」「等待后端就绪… 12s」）。
3. **展示时机**：主窗体 `Shown` 后立即显示；`Boot()` 成功（后端 + dsh 就绪）后关闭；
   失败则切到错误态，提供「重试」（重跑 `Boot`）与「打开日志」。
4. 等待期显示**已用时 / 剩余倒计时**（`WaitHealth` 现为固定 45s 轮询，可暴露剩余秒数）。
5. 保留现有状态灯 / 日志，作为就绪后的常驻指示。

## 验证
- 冷启动（后端未运行）：出现遮罩，文本随阶段变化，后端就绪后自动消失进入主界面。
- 后端启动失败 / 超时：遮罩显示失败原因，重试可用。
- 后端已在运行：遮罩一闪而过或跳过，不明显闪烁。
- 不影响 `Shown` 后其它业务页初始化。

## 风险 / 注意
- 低-中：纯 UI 层；`Boot()` 在**后台线程**，所有 UI 更新必须 `Invoke`（跨线程）。
- `PrepareEnv` 可能弹 UAC / 装包很久，遮罩要能体现「正在安装依赖」而非看似卡死。
- 遮罩不得阻塞主线程（否则假死）。
