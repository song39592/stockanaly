# 后期待办：回测「破产」截断（净值归零 / 跌破阈值）

## 背景
回测编排在 `backend_fastapi/strategies/core/backtest.py` 的 `run_backtest()`（:140），
真正的净值与指标引擎在 `backend_fastapi/strategies/core/stats.py` 的 `compute()`（:210），
净值递推循环在 `stats.py:314-351`。

**现状（无破产概念）**：
- 净值可以合法跌破 0，循环**全程跑完、不因净值归零而停止**（`stats.py:314-351` 里没有 `if nav <= 0: break`）。
- 只有「非有限值收敛」式的兜底，没有业务截断：
  - 净值 ≤ 0 时把 `annual_return` 置 `None` — `stats.py:379-388`；
  - 回撤用 `running_max`、除零归一到 −1 — `stats.py:389-394`；
  - 成本吃光净值只给一个**告警 flag**（`cost_drag`），不截断 — `stats.py:366-378`。
- 代码里搜 `破产` / `归零` / `爆仓`：**0 命中**（仅出现在注释/文档的比喻里，如 `stats.py:279` 「净值 −100.1%」、`:381` 「已爆仓」）。
- 结果里没有破产标记、没有触发日期；净值序列可以一路变负。

## 目标
支持**破产截断**：当组合净值 ≤ 阈值（默认 0）时判定破产，**自该日起截断**——
停止后续交易 / 换仓 / 成本计提，净值冻结在破产日（或按清算约当结算），
并在结果与净值曲线上标注「破产点 + 触发日期」。未触发时行为与现在**逐字段一致**。

## 具体步骤
1. **入参**：`run_backtest(...)` 增加 `bankrupt_at: float | None = 0.0`，透传到 `stats.compute`；
   默认 `0.0` = 「净值 ≤ 0 判破产」，`None` = 关闭（退化为旧行为）。
2. **循环内截断**：在 `stats.py:314-351` 递推里，算完当日 `nav[t]` 后判断
   `nav[t] <= bankrupt_at` → 记 `bankrupt_index/day = t`，把其后 `nav[k]` 冻结为破产值、
   后续 `R / dw_all / turnover / cost` 一律按 0 处理，然后 `break` 出循环。
3. **输出字段**：`stats` 结果增加 `bankrupt`(bool) / `bankrupt_date` / `bankrupt_index`；
   净值曲线在破产日之后保持水平（长度不变，便于前端对齐）。
4. **报告 / 前端**：`strategies/report.py:224-228` 落盘的 `equity/dates` 仍为完整长度（冻结值）；
   `launcher/StrategyPage.cs:1610` 净值曲线上标注破产点（阈值线 + 标签，可选）。
5. **指标口径**：破产时 `annual_return / max_drawdown` 按**截断到破产日**的序列计算，
   不再用变负的净值硬算；指标卡上显示「已破产」。
6. **边界**：`bankrupt_at` 允许设 `-0.2` 之类（允许一定回撤才算破产）；破产日不再计提成本。

## 验证
- 构造**必然破产**的策略（满仓单只暴跌/退市标的）跑回测：净值在阈值处截断、其后无交易、
  `bankrupt=True` 且日期正确。
- 未触发破产的策略：结果与改动前**逐字段一致**（回归对比，建议加单测）。
- `csc` 编译前端通过；重建 EXE 后冒烟。

## 风险 / 注意
- 中：改动落在回测核心递推循环，**必须保证未触发时零行为差异**（先加对比测试再改）。
- 语义待定：破产后净值是「冻结在破产值」还是「清算到 0」，需确认口径。
- 阈值口径：本待办按「组合净值」判定；若要按「单票市值归零」另议。
