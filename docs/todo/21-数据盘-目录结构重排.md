## 问题
数据盘 `E:\stockanaly-data` 现在**扁平堆放**：用户配置、数据库、行情分片、锁文件全在同一层，
没有任何 `logs/` 与 `cache/` 目录。

## 现状（`E:\stockanaly-data`）
| 条目 | 类型 | 说明 |
|---|---|---|
| `bars/` | 目录 | 行情库分片，**41 个文件 2098.8 MB** |
| `chip/` | 目录 | SCR 数据与计算结果，12 文件 0.2 MB |
| `history_stock_view.json` | 文件 | ⚠️ **用户配置**（查看历史/视图状态），却躺在根目录 |
| `stock_history.db` | 文件 | 持久化状态 |
| `mentor_lab.db` | 文件 | 持久化状态 |
| `instance.lock` | 文件 | 运行期锁 |

数据根目录由 `config.py:80 DATA_DIR = _resolve_data_dir()` 决定，
优先级：`STOCK_DATA_DIR` > `.env` 的 `DATA_DIR` > 默认 `PARENT_DIR / "stockanaly-data"`（即仓库**上一级**目录，不依赖盘符）。
各子目录常量集中在 `backend_fastapi/storage.py`（`CHIP_DIR` 等）。

## 建议目标结构
```
E:\stockanaly-data/
├─ config/      ← 用户配置集中
│  ├─ history_stock_view.json      （从根目录迁入）
│  └─ （以后新增的 ui/视图/阈值 等用户可改配置都放这里）
├─ state/       ← 持久化状态
│  ├─ stock_history.db
│  ├─ mentor_lab.db
│  └─ instance.lock
├─ bars/        ← 行情分片（保持）
├─ chip/        ← SCR（保持）
├─ logs/        ← 新增（第 22/23 项的落点）
└─ cache/       ← 新增（可重建缓存，从源码树挪出来的部分）
```

## 建议做法
1. 在 `storage.py` 里把上述子目录**收成一组常量**（`CONFIG_DIR` / `STATE_DIR` / `LOGS_DIR` / `CACHE_DIR`），
   其它模块一律引用常量，不再各自拼路径。
2. 做**一次性自动迁移**：启动时若发现旧位置有文件而新位置没有 → 搬过去（写日志说明）。
   别要求用户手动拷。
3. `history_store` / 各 service 里写死 `<data>/xxx.db` 的地方改为引用 `STATE_DIR`。

## 注意（踩坑点）
1. **`bars/` 有 2.1 GB，绝不能移动**（41 个分片，移动既慢又易中断）—— 目标结构里它**保持在根**。
2. 迁移必须是**非破坏性**的：搬完先校验新文件可读，再删除旧的；失败要保留原状并提示。
3. 数据盘在仓库外，改动**不会**被 git 跟踪 —— 所以**必须靠自动迁移逻辑**保证老用户升级后不丢配置，
   不能指望「提交里带上新目录」。
4. 用户换过 `DATA_DIR`（`.env` 里指定到别的盘）时，迁移逻辑同样要生效 —— 用 `DATA_DIR` 解析，别硬编码 `E:\`。
5. `instance.lock` 是运行期锁，迁移时要确认没有别的实例正在持有（否则会误判单实例冲突）。
