## 问题
`Color.FromArgb(...)` 在 `launcher/` 里硬编码 **146 处**，同一语义存在多套 RGB，
且这些「语义色」完全不参与换肤（`BuildPalette()` 只维护 `_cBg/_cPanel/_cSub/_cText` 四个底色）。

## 建议做法
1. 新建 `launcher/Palette.cs`（partial class MainForm 之外的一个 `internal static class C`）：
   `Up / Down / Flat / Warn / Err / Ok / Accent`，另加 ChipPanel 需要的 `ProfitDark / ProfitLight`（保留深浅两份）。
2. 把 146 处 `Color.FromArgb(...)` 按语义替换成 `C.Up` 等。
3. **先不要**把它们纳入 `BuildPalette()` 换肤 —— 本项只做「常量化」，视觉零变化。

## 注意（踩坑点）
- `(208,57,59)` **同时被当「涨红」和「错误红」用**（见 StrategyPage.cs:706 `pnl>=0 ? (208,57,59) : (60,160,90)`）。
  替换时要按**当前位置的实际语义**选 `C.Up` 还是 `C.Err`，不要机械地统一成一个。
- ChipPanel 的深浅双份必须保留两个值（`ProfitDark`/`ProfitLight`），不能折中。
- `Skin()`（StockPoolLauncher.cs:958）有个 `tag == "mkt-dir"` 分支专门**跳过换肤以保留涨跌色** ——
  说明作者撞过「换肤冲掉涨跌色」的坑，但只给盘面页打了补丁。本次不动它，只做常量化。
