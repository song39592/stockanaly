# bug-03 · 前端：K 线图偶发整块变白（未换肤态），重启才恢复

> 状态：**已修复（防御性组合拳）**　|　2026-10-06　|　用户报告，附截图

## 现象（用户描述 + 截图证据）

- 深色主题下，K 线图整块**变白**；左轴价格刻度与底部日期仍是深色，且
  左轴出现**两套不同刻度叠印**（旧帧残留）；09-04 处有一根**贯通上下的巨红柱**
  （某次放大视图下那根大阳线的残影）。
- 触发：**点「分析」切股票之后**；频率几天一次；**怎么操作都不消失，重启才恢复**。
- 用户全程深色主题（`_light` 不持久化，未切过）。

## 定性（截图给出的确定结论）

白块 = **KLineChart 处于「从未被 Skin 过」的默认配色**在自绘：
`OnPaint` 第一行就是 `FillRectangle(BackColor)`，而图例 `日K MA5…` 是
**黑字白底**（`SystemColors.Control` ≈ 240 白 + 默认黑 ForeColor）——
正常深色皮肤下应是浅字深底。深色的轴区/巨红柱则是**旧帧屏幕残留**。

## 排查过程（为什么最后选了防御性组合拳）

1. `KLineChart.OnPaint` 全部 6 处 `FillRectangle` 逐行核对 —— 无一处能画出
   「白色 + 覆盖整个绘图区」的矩形；图表自身只会用 `BackColor` 铺底。
2. 图表上无叠加控件（kLayout 只有两列：图表 + 178px 筹码面板）；
   `ChartKit.SetStyle` 含 `ResizeRedraw`，非尺寸残留问题。
3. `SetData` 走 `Invoke` 回 UI 线程且带 round 守卫，非线程竞争。
4. `SubTabStrip.Select(0)` 每次挂载都会 `Skin(page)`（`Select` 里有 `_app.Skin(page)`）；
   `ApplyTheme` 会递归全部**已挂载**控件 —— 静态上「图表从未被染过」不应发生。
5. 启动器有 `Application.ThreadException` 弹窗，用户从未见过报错 ——
   「Skin 抛异常中断递归」的假说缺最后一环证据（哪个控件、为何抛）。

**结论：能确证症状与机制的一半（未换肤控件自绘），无法静态确证漏染的那条路径。**
因此采取「保险丝 + 证据 + 硬化」三层修复，并把取证留给运行期日志。

## 修复（5 处，均带 ⭐ 注释标记）

| # | 位置 | 内容 | 性质 |
|---|---|---|---|
| 1 | `StockRenderHistory` | 每次数据渲染前 `Skin(_stockKline); Skin(_stockChip);` | **保险丝**：无论根因是什么，图表最多白一帧，不可能白到重启 |
| 2 | `SelectTab`（顶层） | 显示页面后 `Skin(_tabPages[index])` | **对称补齐**：二级页挂载会 Skin，顶层页原先只切 Visible 从不重染 —— 页内后加的控件永远漏染 |
| 3 | `BuildIndicatorToggles` | 重建完勾选框后 `Skin(_stockIndFlow)` | **实锤 bug**：每次点「分析」都会异步重建指标勾选框，`Check()` 不设 BackColor（默认 `SystemColors.Window` 白底）、`Lbl()` 硬编码黑字，深色下分组标签直接不可见 —— 之前无人补染 |
| 4 | `KLineChart.Zoom` / `SetData` | `_tip.Hide(this)` | **实锤 bug**：`_tip.Show(text, this, x, y)` 没给时长参数会一直挂着；滚轮缩放/换股后浮窗冻结在旧位置显示旧数据 —— 深色下就是白色小方块（用户「白块」症状之一） |
| 5 | `Skin` / `SkinColors` | 染色与逐子递归全部 try/catch + `LogSkinFault` 落 `skin_error.log` | **取证 + 硬化**：任何控件换肤抛异常只牺牲自己、不再拖累兄弟控件漏染；同时留下控件类型与堆栈，根因若再现即可定位 |

`skin_error.log` 已被既有 `.gitignore`（`*.log`）覆盖，不会进版本库。

## 验证

- `csc` exit 0，无 lint。
- 实跑 45 秒：窗口正常、无 `.NET Runtime` 事件、正常关闭（后端 8000 随之回收）。
- 实跑期间 `skin_error.log` 未生成 —— 说明本次换肤路径无控件抛异常、无误报。
- **待用户实跑数日观察**：白块是否复现；若复现，看根因的两条判据：
  - `skin_error.log` 出现 → 里面有控件类型与堆栈，根因直接落地（对应修复 5 的取证）；
  - 白块仍出现但图表**一次数据渲染后即恢复深色**（修复 1 生效）→ 说明漏染发生在
    「启动后首帧」而不是渲染路径，再沿 SelectTab/Select 的调用序追。

## 给「无法静态定位」记一笔

这次最大的教训不是没找到根因，而是**先把能确证的都确证了再动手**：
截图先定性（黑字白底 = 未换肤自绘；两套刻度 = 旧帧残留），排除法收窄
（线程竞争/叠加控件/绘制逻辑/ResizeRedraw 全部排除），最后在
「Select 会 Skin」与「实际未 Skin」的矛盾上承认静态分析到头，转而用
「保险丝（症状必治）+ 日志（根因取证）」收口。**宁可带证据回来，不带猜测硬修。**
