# 04 · 前端：股票名称获取合一（约 30 行逐字重复）

> 状态：待办　|　优先级：高　|　收益 ★★★★☆ / 风险 ★☆☆☆☆

## 问题
个股页与估值页各自写了一遍「调 `/api/stock/quote` 拿名称+现价」，逻辑几乎完全相同。

## 证据

| | `StockLoadName(code)` StockPage.cs:670 | `ValuationLookupName()` ValuationPage.cs:348 |
|---|---|---|
| 取 code | 参数传入 | `_vCode.Text.Trim()`（:350） |
| 6 位校验 | 无（调用方 `StockOpen`:642 已校验） | 有（:351） |
| URL | `/api/stock/quote?code=` + code（:676） | 同（:356） |
| 请求 | `VRequest(url, null)`（:676） | 同（:356） |
| 反序列化 | `JavaScriptSerializer`（:677） | 同（:357） |
| 竞态守卫 | `if (_stockCode.Text.Trim() != code) return;`（:680） | `if (_vCode.Text.Trim() != code) return;`（:360） |
| ok 判定 | :682 | :362 —— **逐字相同** |
| 成功分支 | `VNum(VSafe(j,"price"))` + `VStr(VSafe(j,"name"))` + `pr.ToString("F2")+" 元"`（:685-687） | :365-366 —— **逐字相同** |
| catch 文案 | `"名称查询失败：" + ex.Message`（:698） | 同（:377） |

差异只有三处：
1. 个股页多了 `StockAddHistory(code, nm)`（:688，补历史记录名称）—— **副作用**
2. 估值页失败时多一层兜底：`e2=="" ? "未找到该代码对应的股票" : e2`（:370-371）
3. 写入的控件不同（`_stockName` vs `_vName`）

## 建议做法
抽一个公共方法：
```csharp
private void FetchStockName(string code, Action<string name, double? price> onOk, Action<string> onFail)
```
两个调用方各自在回调里写自己的控件。

## 注意（踩坑点）
- `_stockName` / `_vName` 是两个不同控件，只能靠回调解耦。
- 失败兜底文案不同（个股页显示空、估值页显示「未找到该代码对应的股票」）—— 统一成哪一句都要过一次视觉确认，
  建议**保留各自文案**，由 `onFail` 传入。
- `StockAddHistory(code, nm)` 是个股页**副作用**，不能共享，留在个股页的 `onOk` 里。
- 竞态守卫依赖两个不同输入框（`_stockCode` / `_vCode`）；抽出后守卫留在调用侧（回调里已带 `code`，可比较）。
