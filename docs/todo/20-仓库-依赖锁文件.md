## 问题
只有**依赖声明**，没有**锁文件** —— 同一份 `requirements.txt` 在不同时间装出来的版本可能不同，
出问题后无法复现「当时到底装了什么」。

## 现状
| 文件 | 位置 | 说明 |
|---|---|---|
| `requirements.txt` | `backend_fastapi/requirements.txt` | 10 行，**无版本约束**：fastapi / uvicorn / akshare / requests / beautifulsoup4 / pydantic / python-dotenv / pypdf / python-multipart |
| `package.json` + `package-lock.json` | `agent_dsh/` | ✅ **这一侧已经有锁文件** |
| 无 | `backend_fastapi/` | ❌ 缺 `requirements.lock.txt` |

虚拟环境位置：`backend_fastapi/venv`（启动器 `FindPython` 同时探测 `.venv` 与 `venv`，见 StockPoolLauncher.cs:1507-1508）。

## 建议做法
1. 在 `backend_fastapi/` 生成 `requirements.lock.txt`：用现有 venv 执行 `pip freeze`（**只输出本环境实际安装的主依赖及其精确版本**）。
   - 注意：`pip freeze` 会把传递依赖全部列出（numpy/pandas/requests 的子依赖等），这是**锁文件该有的样子**，不要精简。
2. 在 `requirements.txt` 顶部加注释，说明两者区别：
   ```
   # 声明文件：只写直接依赖，不锁版本（便于升级）
   # 锁文件见 requirements.lock.txt（pip freeze 生成，用于复现环境）
   ```
3. 可选：在 `setup_backend.bat` 里增加「按锁文件安装」的参数分支（默认仍按 `requirements.txt` 装）。

## 注意（踩坑点）
1. **`pip freeze` 必须在 `backend_fastapi/venv` 里跑**，不能拿系统 Python 的结果。
2. 锁文件里**不要**包含本地路径安装（`-e file:///...`）或 `pkg==x @ file://` 这类条目 —— 若有，说明环境里有本地安装的包，需先确认是否需要。
3. `akshare` 版本很关键：它频繁变更接口字段，`stock_info_a_code_name`、`stock_profile_cninfo` 等字段名随版本变化 ——
   锁文件能固定住这些敏感依赖，是本项目最实际的收益。
4. 锁文件**要提交**（它属于「依赖声明与锁文件」这一类，不是构建缓存）。
