# 26 · 前端：启动器公共件归位（GridKit / Cards / J / C 等别再散在各页文件里）

> 状态：待办　|　优先级：中　|　收益 ★★★☆☆ / 风险 ★☆☆☆☆

## 问题
启动器是按页面拆的（每页一个 .cs），但**被多个页面共用的控件/工具**目前散落在各自的页面文件里，
跨文件互相调私有静态方法，读起来像「个股页的东西被盘面页依赖」。

## 现状
`launcher/` 现有文件：`StockPoolLauncher.cs`（骨架+换肤+服务）、`StockPage.cs`、`StrategyPage.cs`、
`MarketPage.cs`、`ValuationPage.cs`、`DownloadPage.cs`、`ChipRankPage.cs`、`GridKit.cs`。

已知确实存在「公共件住在某个页面文件里」的情况：
| 公共件 | 现在的位置 | 被谁调用 |
|---|---|---|
| `AddKpi` / `VKpiRow` | `ValuationPage.cs:213 / :185` | **3 个页面共 24 处**（详见第 06 项） |
| `VSafe` / `VStr` / `VNum` / `VArr` 等 JSON 工具 | `ValuationPage.cs` | 各页（详见第 02 项） |
| `GetText` / `PostJson` / `Probe` | `StockPoolLauncher.cs:2565 / :2523 / :2466` | 各页（详见第 03 项） |
| `NewPage/Stack/Group/Row/AddRow/MiniBtn/Lbl/Mute/Dot/Check` | `StockPoolLauncher.cs:675~1475` | 各页 |

`GridKit.cs`（第 01 批刚做的 `StockGrid` + `GridColumn` + `OpenStock`）是**正确的先例**：独立文件、跨页共用。

## 建议做法
按 `GridKit.cs` 的模式，把公共件拆成独立文件（都是 `partial class MainForm`，拆文件不用改调用）：
- `GridKit.cs` —— 表格（已有）
- `UiKit.cs` —— 页面骨架与控件工厂（`NewPage/Stack/Group/Row/AddRow/MiniBtn/Lbl/Mute/Dot/Check/FlatBtn`）
- `Cards.cs` —— KPI 卡片与卡片行（`AddKpi` / `VKpiRow`，即第 06 项的落点）
- `J.cs` —— JSON 工具（第 02 项的落点）
- `Palette.cs` —— 色彩常量（第 01 项的落点）
- `Http.cs` —— HTTP 封装（第 03 项的落点）

## 注意（踩坑点）
1. 这些都是 `partial class MainForm` 的成员，**拆到新文件不需要改任何调用点**，是零风险搬家 ——
   唯一要动的是 `build_exe.bat` 的源文件清单（多加几行 `.cs`）。
2. `build_exe.bat` 里源文件顺序不影响编译（C# 无顺序要求），但**新增文件必须登记**，否则不会参与编译。
3. 别一次性全搬：**建议在做第 01/02/03/06 项时顺手把对应公共件落到新文件**，而不是单独做这一项搬空壳。
   本项更像「约定」而非独立改动。
