## 数据目录问题的实际原因

审查时后端 `/api/system/storage` 返回 `C:\stockanaly-data`，而 `.env` 已保存 `DATA_DIR=D:\stackdata`。
这说明保存已落盘，但当前后端尚未加载新配置。

1. **“保存并重载”没有执行重载。** 它只写配置，然后立刻读取仍在运行的后端，把输入框刷回旧路径。
2. **读取路径多截了一个字符。** 启动器用 `Substring(10)` 读取长度为 9 的 `DATA_DIR=` 前缀，盘符首字母会丢失；`STOCK_DATA_DIR=` 也有同样错误。
3. **退出桌面程序不等于重启后端。** 外部启动的服务会被继续复用，重开窗口仍使用旧配置。
4. **数据迁移提示与实现不符。** 原提示承诺旧数据会自动补齐，实际只复制项目内的遗留目录；不会搬走当前外部目录中的行情分片、下载任务及其设置。

修复：显示“当前使用 / 已保存 / 待重启”，拆成“保存目录”和“重启后端生效”，修正路径解析和优先级；异步刷新不覆盖新编辑。重启等待旧进程停止后才启动新进程，并显示失败结果。

后端写配置使用原子替换并保留备份；拒绝相对路径和控制字符；兼容路径空格、单引号和 `#`；清理重复数据目录项。若父进程环境变量覆盖数据目录，明确拒绝无效保存并告知原因。

## 下载及其他设置的缺陷

| 级别 | 原行为与影响 | 本地修复 |
|---|---|---|
| P1 | 自动更新先写入再校验，报错却已开启；一组设置可能只保存一部分 | 先校验，单事务保存 |
| P1 | 两个开关都随每次请求提交，快速操作和慢响应可能覆盖另一个开关 | 只提交本次改变的字段；保存期间禁止重复操作，并丢弃过时响应 |
| P1 | 关闭自动下载开关不停止已经运行的对应任务 | 取消对应自动任务，保留已下载数据和手动任务；在途单次请求可能仍会完成 |
| P1 | 暂停后继续会重排仍在处理的记录，可能重复下载；强制重试可替换尚未退出的 worker | 活进程内继续保留在途记录；恢复重启后的孤立记录；等待 worker 收尾后才允许重试 |
| P1 | 服务端没有防止同时启动多套下载任务 | 任务启动和控制串行化，并在新建前检查现有 worker |
| P2 | 重开下载页不恢复任务，只显示“未开始” | 进入页面和后端恢复时查询任务，优先恢复活动或暂停任务 |
| P2 | 容量预估与进度共用请求编号，轮询可能让慢响应一直失效 | 分离编号；进度请求完成前不叠加新请求 |
| P2 | 自动更新不满足条件时连关闭也被禁用，缓存还会返回旧开关值 | 已开启时始终允许关闭；缓存覆盖度但读取最新设置；解释不可开启原因 |
| P2 | 起始年份晚于固定分界年，实际仍从更早年份下载 | 近期阶段取所选起点与分界日期中的较晚者 |
| P2 | 下载启动失败仍标记“今天已调度”，当天不会再尝试 | 成功排队或确认无新增标的后才记录日期 |
| P2 | 保存成功但即时调度失败也被当作“保存失败” | 分开返回保存结果与调度警告 |
| P2 | 失败只显示数量，不显示具体原因；部分失败也显示完成 | 展示股票代码与失败原因，标明“部分失败” |
| P2 | 常规设置捕获异常后，调用者仍弹“已保存”；开机启动异常被吞掉 | 仅成功后显示保存结果，开机启动失败明确报错 |

原交互不合理的核心是：按钮承诺与实际动作不一致，而且没有区分“输入值、已保存值、正在使用值”。多个保存按钮的作用范围也不清晰。

本次已明确保存范围、重启要求、失败原因、后台开关生效状态；下载操作加了重复提交保护。

- **完整任务历史选择器**：当前优先恢复活动/暂停任务，但用户还不能从列表自由查看任意旧任务。
- **后台调度状态面板**：说明下一次自动更新时间与最近一次后台错误。“闲时”当前指没有其他下载任务，未检测电脑是否空闲。
