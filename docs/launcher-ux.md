# 启动器交互反馈（Boot 遮罩 / 失败弹窗）

> 本文是**实现层要求**，不常驻加载 —— 规则区只保留指针（见 `.codebuddy/rules/frontend-conventions.md`）。
> 触发场景：启动流程、后台长任务、安装失败、子进程拉起失败。

## 超过 1 秒的后台任务必须给可见反馈

- 启动流程跑在后台线程上（装依赖可能几分钟、起后端可能十几秒），而主窗体已经显示：
  用户只看到顶部状态灯在变，会以为「双击没反应」。
- 长任务要有**阶段文本**（正在做什么：检查环境 / 装依赖 / 等后端就绪）+ **已用时 / 剩余倒计时**，
  让等待可见（而不是一片空白）。

## 但不要挡住「本来就能用」的界面

- 遮罩只在**真要等某个东西**时出现：启动时先探一次后端，**已经在跑就不弹遮罩**，界面立即可用。
- 判断标准：遮罩挡住的是「用户本来就能干的事」→ 不弹；挡住的只是「反正也干不了」的等待期 → 才弹。

## 失败必须能重试

- 失败切错误态：停进度条、写清原因、给「重试」（重跑流程）与「查看日志」（跳运行日志页）。
- 重试要复位状态（阶段文本、秒表、按钮可见性），不要留上一次的残影。
- 重试前要判重：已经在跑就别再起一条并行流程。

## 错误弹窗要给「可执行的下一步」

- 原因要人话（退出码 → 中文原因），别只丢「未知错误」。
- 日志要给「开头 + 关键错误行 + 末尾」三段（根因常在最前面，只给尾部会误导排查方向）。
- 附一条可直接复制的手工排查命令。

## 状态更新走统一通道

- 后台线程 → UI 的更新统一走 `Ui(...)`（BeginInvoke）/ `UiSync(...)`（Invoke），
  不要在后台线程直接碰控件。
- 页面级耗时任务也复用同一套「阶段回报 + 日志」通道，不要每页各写一套。
